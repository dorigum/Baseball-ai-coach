## 4. 트러블슈팅 및 해결 이력

### 16. 주자명(String) 도입 시 백엔드 API와의 타입 불일치 (JSON 파싱 에러) 조치

- **문제 현황**: `runners` 상태를 주자명 문자열(String)로 고도화한 후, AI 전술 조언 요청 API 호출 시 문자열 값을 그대로 실어보내 백엔드에서 JSON 파싱 에러(400 Bad Request)가 발생함.
- **원인 분석**: 백엔드 `AdviceRequestDto`가 수용하는 `firstBase`, `secondBase`, `thirdBase` 필드가 원시 boolean 타입으로 선언되어 있어 Jackson 라이브러리가 일반 이름 문자열(예: `'신민재'`)을 boolean으로 역직렬화(Deserialization)하지 못해 컴파일 예외 발생.
- **해결 방안**: 프론트엔드의 `handleTriggerAiAnalysis` API 요청 본문 작성 시, `!!runners.first`와 같이 이중 부정(Double Negation) 연산자를 사용해 문자열의 존재 여부를 boolean 값으로 형변환하여 전송하도록 보완하여 백엔드 API 규격을 엄격히 보존함.

### 17. 팀 매칭 변경 시 기존 주자 정보 및 볼카운트가 초기화되지 않고 화면에 잔존하는 현상 조치

- **문제 현황**: 대화형 SVG 야구장에서 주자가 진루한 상태(예: 1루 주자 `'신민재'`)이거나 볼카운트가 진행 중일 때, 경기 메타 설정에서 우리 팀이나 상대 팀을 변경하여도 기존 주자 및 카운트 정보가 그대로 유지되는 데이터 정합성 결함 발생.
- **원인 분석**: `App.jsx` 내의 팀 변경을 처리하는 `useEffect` 훅이 defenders, battingOrder, pitchInfo만 갱신하고 `runners`와 `count` 상태를 리셋해주는 초기화 로직이 누락되어 기존 데이터가 렌더링에 영속화됨.
- **해결 방안**: 팀 변경 감지 훅(`useEffect` 의존성 `[defendingTeam, attackingTeam]`) 내부에 `setRunners({ first: '', second: '', third: '' })` 및 `setCount({ balls: 0, strikes: 0, outs: 0 })` 초기화 구문을 추가하여 팀 변경 시 모든 상황 데이터를 깨끗하게 초기화시킴.

### 18. 새로고침(F5) 시 입력해 둔 구단/선수 정보 및 상황판 데이터 전체가 증발하는 현상 개선

- **문제 현황**: 기타 구단명 및 사용자 지정 선수 라인업, 실시간 투구 로그 등의 데이터를 정성껏 입력해 둔 상태에서 브라우저를 새로고침(F5)하면 모든 React 상태가 초기화되어 기입했던 정보가 유실됨.
- **원인 분석**: 모든 경기 진행 상태(runners, count, scores, defenders, battingOrder 등)가 단기 메모리인 React state로만 관리되고 있어 새로고침 시 초기 컴포넌트 마운트 값으로 리셋됨.
- **해결 방안**: 
  1. 각 state의 기본값을 Lazy Initializer 기능을 사용해 `localStorage.getItem`에서 꺼내와 파싱하여 로드하도록 고도화.
  2. 각각의 state 변경을 감지하는 `useEffect`들을 추가해 `localStorage.setItem`으로 실시간 디스크 동기화.
  3. 팀 설정 변경을 자동 동기화하는 기존 `useEffect`가 첫 마운트 시 `localStorage`로부터 복원된 데이터를 덮어쓰지 않도록 `useRef` 기반의 `isFirstRender` 라이프사이클 가드를 도입해 정합성 수호.
  4. 강제 초기화가 필요할 때를 대비해 로컬 스토리지를 일괄 소거하는 '🧹 경기 데이터 초기화' 버튼 기능 추가 구현.

### 19. 홈런 구역 가이드라인 은폐 결함 및 뷰포트 해상도 축소 시 스코어보드 UI 레이아웃 깨짐 현상 조치

- **문제 현황**:
  1. 가이드라인 상의 황색 홈런 라인(y=45)이 화면에 렌더링은 되나 유저의 시야에 전혀 보이지 않는 현상.
  2. 브라우저 크기를 태블릿 이하로 축소시킬 시, 스코어보드 내의 상대 팀 엠블럼 박스(로고)가 카드 테두리 우측 밖으로 삐져나가 오버플로우를 유발하고 헤더 버튼의 폭이 망가지는 현상.
- **원인 분석**:
  1. `BaseballField.jsx`에 들어있던 드래그/시프트 안내 카드가 `absolute top-4` 스타일로 SVG 박스 내부의 상단 영역(y=0~100)을 넓게 뒤덮고 있어 그 밑에 렌더링된 홈런 구역(y=45)과 문구가 완전히 가려짐.
  2. 스코어보드 카드가 모바일 분기점인 `md`(768px) 기준만 적용하고 있어, 가로 폭이 800px ~ 1000px 구간일 때 억지로 flex-row(가로 정렬) 배치를 시도하다 내부 요소(팀 로고, 스코어 증감 버튼)의 고정 폭 한계를 견디지 못하고 넘쳐흐름.
- **해결 방안**:
  1. 가이드 카드를 `BaseballField.jsx` 컴포넌트 내부에서 완전히 들어내고, `App.jsx`에서 야구장 컴포넌트 상단 위에 단독 레이아웃 카드로 배치하여 SVG 야구장의 상부 영토를 100% 개방함 (홈런 라인 및 텍스트 시야 확보 완료).
  2. 스코어보드와 헤더의 플렉스 정렬 분기점을 대형 태블릿 기준인 `lg`(1024px)로 대폭 상향 조정하여 모바일 및 태블릿 공간에서 여유롭게 수직 정렬(`flex-col`)을 수행하게 조치하고, 래퍼들의 가로폭(`w-full`)을 안전하게 복원하여 전 뷰포트 대응을 완수함.
