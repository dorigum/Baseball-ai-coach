# 2026-07-24 개발 기록

Baseball AI Coach 프로젝트의 프론트엔드 UI/UX 설계 및 대화형 시각화 화면 구축 완료에 이어, 백엔드 API 서버(Spring Boot + MySQL)의 뼈대와 DB 엔티티 설계/구축 완료. 수비/공격 팀에 따른 야구장 라인업 동적 정합성 보완, 실시간 수비 라인업 및 실시간 공격 타순(1~9번) 관리 에디터 추가 적용 완료. 추가적으로 Spring AI와 Google Gemini API(gemini-3.5-flash-lite) 연동 및 실시간 전술 분석 추천 API 서비스 구축 완료.

## 📅 주요 작업 내역

### 1. 프론트엔드 React 개발 환경 세팅
- **Vite + React 19 + JavaScript** 기반 템플릿 설치.
- **Tailwind CSS v4** 플러그인(`@tailwindcss/vite`)을 `vite.config.js`와 `src/index.css`에 주입하여 스타일링 기반 확립.
- **lucide-react** 및 **recharts** 시각화 패키지 추가.

### 2. 프론트엔드 컴포넌트 설계 및 구현
- **[BaseballField.jsx](../../frontend/src/components/BaseballField.jsx)**:
  - 9명의 수비수 마우스/터치 드래그 수비 시프트 시뮬레이션 및 필드 클릭 좌표 캡처, 베이스 주자 클릭 토글 기능 연동.
  - 수비수 호버 툴팁: 수비수 배지에 호버 시 상세 포지션 풀네임, 선수명, 소속구단 노출.
  - 전광판 공수 뱃지: 이닝진행 상태에 맞추어 공격 구단(Red 🔥) 및 수비 구단(Emerald 🛡️) 정보를 실시간 계산해 표기.
- **[PlayInputPanel.jsx](../../frontend/src/components/PlayInputPanel.jsx)**: 경기 날짜, 구장 프리셋(잠실, 인천 등), 우리 구단 vs 상대 구단, 이닝 정보 설정 창 장착 및 실시간 공수 인디케이터 장착. 선수 이름/소속팀 폼 및 구종/구속/SBO 카운트 제어판 구축.
- **[Dashboard.jsx](../../frontend/src/components/Dashboard.jsx)**:
  - Recharts 기반 구종 도넛 차트, 타구 스프레이 2D 차트, 타격 바 차트 시각화 및 세션 로그 테이블 연동. AI 조언 박스 구성.
  - 실시간 수비 라인업 설정 카드 탑재: 우측 대시보드 상단에 9개 수비 포지션별 선수 목록 카드를 배치. 각 선수명을 클릭하면 인풋창으로 변환되어 대수비나 투수 교체 등 실시간 라인업 변동 사항을 사용자가 수동 수정할 수 있도록 구현.
  - 실시간 공격 타순 설정 카드 탑재: 현재 공격 중인 구단(attackingTeam)의 1번부터 9번까지의 타순 목록을 시각화. 각 타자 명단을 클릭해 실시간 대타 기용 상황을 사용자가 편집할 수 있도록 구현하였으며, 현재 타석에 선 타자는 `AT BAT` 뱃지와 붉은색 활성 테두리(Red Pulse)가 표기되도록 연동.
- **[App.jsx](../../frontend/src/App.jsx)**:
  - 스트라이크/볼/아웃 누적 연산 및 주자 진루 시뮬레이터.
  - KBO 주요 구단 대표 수비 라인업 및 구단별 대표 1~9번 스타팅 타순 데이터를 상수로 탑재.
  - 수비팀 라인업 동적 정합성 조율: 이닝 초/말에 따른 실제 수비 구단의 라인업 데이터를 실시간 감지 매칭하여 야구장 호버 데이터와 동기화.
  - **Gemini AI 전술 추천 연동**: 룰 기반의 로컬엔진 대신 백엔드의 `/api/coach/advice` REST API를 500ms 디바운스(Debounce) 형태로 비동기 호출해 AI 조언을 실시간 Fetch하도록 리팩토링. 백엔드가 오프라인 상태일 때는 자동으로 로컬 룰 백업 엔진(Fallback)이 작동하도록 견고하게 설계.

### 3. 백엔드 Spring Boot + JPA + H2/MySQL 환경 구축
- **Java 21 + Spring Boot 3.3.2 + Gradle** 기반 백엔드 프로젝트 생성.
- `build.gradle`에 Spring Web, Spring Data JPA, Validation, Lombok, H2 Database, MySQL Driver 의존성 설계.
- **Spring AI 구글 AI 스타터 연동**: `build.gradle`에 `spring-ai-starter-model-google-genai` 의존성 및 1.1.0-M1 BOM 추가 설정.
- **API 키 바인딩**: `application.yml`에 `${GEMINI_API_KEY}` 프로퍼티를 추가해 시스템 환경변수 또는 실행 옵션을 통해 Gemini 호출 권한을 매핑.

### 4. JPA 엔티티 및 다대일(N:1) 연관관계 설계
- **[Player.java](../../backend/src/main/java/com/baseball/ai/coach/domain/Player.java)**: 선수 이름, 소속 팀, 포지션, 배번, 투타 방향성 관리.
- **[Game.java](../../backend/src/main/java/com/baseball/ai/coach/domain/Game.java)**: 경기 일자, 구장 정보, 우리팀/상대팀 정보 및 점수 정보.
- **[PlateAppearance.java](../../backend/src/main/java/com/baseball/ai/coach/domain/PlateAppearance.java)**: 타석 정보 기록. 경기(Game), 투수(Player), 타자(Player)와 N:1 연관관계 매핑 및 이닝, 초/말, 최종 결과 관리.
- **[PitchRecord.java](../../backend/src/main/java/com/baseball/ai/coach/domain/PitchRecord.java)**: 개별 투구별 상세 기록. 타석(PlateAppearance)과 N:1 매핑 및 투구 시퀀스, 구종, 구속, 카운트, 투구 결과 및 타구 좌표(X, Y) 보관.

### 5. DTO, 레포지토리 및 비즈니스 서비스 설계
- **[DTOs](../../backend/src/main/java/com/baseball/ai/coach/dto)**: `PitchRecordRequestDto` (투구 로깅 요청) 및 `DashboardResponseDto` (대시보드 통계 및 이력 반환) 구성.
- **[AdviceRequestDto.java](../../backend/src/main/java/com/baseball/ai/coach/dto/AdviceRequestDto.java)**: 실시간 조언 생성 요청 시 전달할 상황 메타 데이터 명세 구조화.
- **[Repositories](../../backend/src/main/java/com/baseball/ai/coach/repository)**: JPA 레포지토리 4종 및 커스텀 쿼리 설계.
- **[CoachService.java](../../backend/src/main/java/com/baseball/ai/coach/service/CoachService.java)**: 저장 및 타석 종결 처리 판별 엔진 구현.
- **[AiAdviceService.java](../../backend/src/main/java/com/baseball/ai/coach/service/AiAdviceService.java)**: Spring AI의 `ChatModel`을 주입받아 경기장 특징, 볼카운트, 투수-타자 상성, 시프트 대형을 프롬프트 템플릿에 녹여 Gemini API로부터 정교한 KBO 전술 조언을 도출하는 핵심 비즈니스 로직 작성.
- **[CoachController.java](../../backend/src/main/java/com/baseball/ai/coach/controller/CoachController.java)**: `/api/coach/pitch` (저장), `/api/coach/dashboard` (대시보드), 및 `/api/coach/advice` (실시간 전술 조언 획득) API 엔드포인트 구현 완료.

### 6. 코드래빗(CodeRabbit) AI 리뷰 피드백 리팩토링 및 안정성 강화
- **의존성 버전 상향**: `spring-ai-starter-model-google-genai` 라이브러리의 Milestone 안정 맵핑을 위해 `build.gradle` 내 `springAiVersion`을 `1.1.0-M1`으로 상향 튜닝했습니다.
- **불필요한 설정 제거**: `application.yml` 내 `gemini-3.5-flash-lite` 모델에는 temperature 조절 옵션이 무시되므로, 400 에러 사전 차단을 위해 `temperature: 0.7`을 삭제했습니다.
- **입력 유효성 검증(Validation) 추가**: `AdviceRequestDto`에 `@NotNull`, `@NotBlank`, `@Min`, `@Max` 제약사항을 추가하고 `CoachController` 파라미터에 `@Valid`를 부여하여 비정상 입력 시 500 에러를 사전에 차단했습니다.
- **예외 전파 및 503 에러 계약 처리**: AI 서비스 관련 예외(`TransientAiException`, `NonTransientAiException`, `RestClientException`)만 catch하여 503 에러로 가공 처리하고, NullPointerException 등 개발자 내부 런타임 오류는 WAS 단으로 그대로 전파하여 500 상태코드로 분리 처리되도록 리팩토링했습니다.
- **문서 앵커 링크 교정**: 일지 문서 하단 트러블슈팅 링크 앵커가 `TROUBLESHOOTING.md` 헤더 구조와 불일치하던 버그를 수정하여 유기적으로 동작하도록 보완했습니다.
- **프론트엔드 폴백(Fallback) 함수 일원화**: `App.jsx` 내 네트워크 에러 및 백엔드 non-2xx 에러 상황 모두에 대해 동일한 로컬 룰엔진 폴백(`triggerLocalFallback()`)이 작동되도록 로직을 깔끔하게 격리 추출하여 복원했습니다.

## 🚨 트러블슈팅 및 에러 조치 내역

### 1. PowerShell 환경에서의 `&&` 연산자 에러
- **원인**: Windows PowerShell 환경에서 `&&` 체이닝 연산자를 사용하여 npm 패키지 설치 시 구문 파싱 에러 발생.
- **해결**: 명령어를 분리하여 순차적으로 실행하여 안정적인 패키지 주입 완료.
- **상세**: [TROUBLESHOOTING.md #1](../TROUBLESHOOTING.md#1-powershell-환경에서의-&&-연산자-에러)

### 2. npm 라이브러리 설치 시간 초과에 따른 비동기 대기
- **원인**: `recharts` 및 `lucide-react` 패키지 다운로드 및 의존성 분석 시 Windows 디스크 및 네트워크 지연으로 인해 3분 이상 소요되어 로컬 커맨드 `WaitMsBeforeAsync`를 초과하여 백그라운드 태스크로 전환됨.
- **해결**: 백그라운드 태스크의 완료 감지 및 `manage_task` 상태 확인을 동반하여 다음 작업을 대기함으로써 안정적으로 의존성 주입 확인.
- **상세**: [TROUBLESHOOTING.md #2](../TROUBLESHOOTING.md#2-npm-의존성-설치-시간-지연에-따른-백그라운드-태스크-전환)

### 3. `getUpdatedDefenders is not defined` React 컴파일 참조 에러
- **원인**: 수비 팀 라인업 바인딩 로직 리팩토링 후, 리액트 스코프에서 제거된 구 버전의 헬퍼 함수 호출 코드가 렌더링 프롭스단에 남아 런타임 ReferenceError 발생.
- **해결**: 컴포넌트에 넘기는 프롭스를 동적 상태 변수 자체(`defenders={defenders}`)로 변경하여 컴파일 정상 복구.
- **상세**: [TROUBLESHOOTING.md #3](../TROUBLESHOOTING.md#3-getupdateddefenders-is-not-defined-react-컴파일-참조-에러)

### 4. Spring AI Google GenAI(Gemini) 의존성 누락 및 application.yml 프리픽스 동기화 에러
- **원인**: 백엔드에 Gemini API 연동을 위해 `spring-ai-google-ai-spring-boot-starter`를 추가하였으나, Gradle 빌드 컴파일 시 버전 정보를 감지하지 못하고 중단되는 현상 및 구식 프리픽스 설정으로 인한 바인딩 불일치 발생.
- **해결**: 라이브러리를 Milestone 1.0.0-M1 BOM 표준 명칭인 `spring-ai-starter-model-google-genai`로 보정 변경하고, `application.yml` 프리픽스를 `spring.ai.google.genai`로 완벽 동기화 처리함.
- **상세**: [TROUBLESHOOTING.md #4](../TROUBLESHOOTING.md#4-spring-ai-google-genai-의존성-누락-및-application.yml-프리픽스-동기화-에러)

### 5. YAML 들여쓰기(Indentation) 오류로 인한 Datasource 바인딩 결함
- **원인**: application.yml 설정 내 H2/MySQL 데이터소스 관련 하위 설정들의 들여쓰기 불일치로 프로퍼티가 매핑되지 않았던 오류.
- **해결**: 데이터소스 자식 속성들의 들여쓰기 4-space 정렬 수정 완료.
- **상세**: [TROUBLESHOOTING.md #5](../TROUBLESHOOTING.md#5-yaml-들여쓰기indentation-오류로-인한-datasource-바인딩-결함)

### 6. 비동기 API 호출 시 이전 레이턴시 요청의 화면 덮어쓰기(Race Condition)
- **원인**: 상황 정보 광클 시 이전의 느린 응답이 최신 화면을 덮어써 데이터가 꼬이는 레이스 컨디션 발생.
- **해결**: AbortController 및 AbortSignal을 fetch 로직에 주입해 이전 요청 즉시 취소 처리 완료.
- **상세**: [TROUBLESHOOTING.md #6](../TROUBLESHOOTING.md#6-비동기-api-호출-시-이전-레이턴시-요청의-화면-덮어쓰기race-condition)

### 7. 백엔드 예외처리 범위 광역화로 인한 내부 결함의 위장 버그 (500 vs 503)
- **원인**: 일반 Exception을 503으로 리턴하여 NullPointerException 같은 자바 런타임 결함이 디버깅에서 가려짐.
- **해결**: AI 서비스 전용 예외(Transient/NonTransient/RestClient)만 503 처리하고, 일반 예외는 500 처리 분리 완료.
- **상세**: [TROUBLESHOOTING.md #7](../TROUBLESHOOTING.md#7-백엔드-예외처리-범위-광역화로-인한-내부-결함의-위장-버그-500-vs-503)

### 8. Spring AI 마일스톤 버전 상의 AssistantMessage.getContent() 컴파일 에러
- **원인**: Spring AI 버전을 `1.1.0-M1`로 상향하면서, AI 메시지 응답 객체에서 텍스트 문자열을 추출하는 메서드 스펙이 변경되어 기호 못 찾음 컴파일 에러 발생.
- **해결**: 호출 코드를 `getText()`로 수정하여 컴파일 무결성 회복.
- **상세**: [TROUBLESHOOTING.md #8](../TROUBLESHOOTING.md#8-spring-ai-마일스톤-버전-상의-assistantmessage.getcontent()-컴파일-에러)

### 9. IntelliJ 캐시/Sync 꼬임으로 인한 Google GenAI Starter 의존성 주입 실패
- **원인**: 백엔드 빌드 시 스프링 AI BOM 버전 상속이 누락되어 버전명이 빈값(`:`)으로 라이브러리 해석이 시도됨.
- **해결**: `build.gradle` 의존성에 버전 명칭인 `:1.1.0-M1`을 직접 박아 꼬임 현상 우회 성공.
- **상세**: [TROUBLESHOOTING.md #9](../TROUBLESHOOTING.md#9-intellij-캐시/sync-꼬임으로-인한-google-genai-starter-의존성-주입-실패)

### 10. 텍스트 입력 중 실시간 API 자동 트리거로 인한 불필요한 토큰 소모
- **원인**: 이름 입력 도중에도 타이머 만료 시마다 API 호출이 반복 발사되어 리소스를 낭비함.
- **해결**: 실시간 자동 fetch를 중지하고 사용자가 직접 수동 조작하는 `🔮 AI 실시간 전술 분석 실행` 버튼을 신설하여 극복함. 동시에 소속팀 및 영어 이름 오타 유효성 검사 경고 팝업을 구축함.
- **상세**: [TROUBLESHOOTING.md #10](../TROUBLESHOOTING.md#10-텍스트-입력-중-실시간-api-자동-트리거로-인한-불필요한-토큰-소모)

### 11. 자동 디바운스 fetch 훅 제거 시 잔여 코드로 인한 리액트 렌더러 컴파일 실패
- **원인**: `useEffect` 제거 시 하단에 중괄호 찌꺼기가 남아 문법 에러를 유발해 React 빌드가 깨짐.
- **해결**: 구식 useEffect 찌꺼기를 말끔히 청소하여 컴파일 완결.
- **상세**: [TROUBLESHOOTING.md #11](../TROUBLESHOOTING.md#11-자동-디바운스-fetch-훅-제거-시-잔여-코드로-인한-리액트-렌더러-컴파일-실패)

### 12. 수동 API 호출 버튼 전환에 따른 비동기 중복 요청(Race Condition) 누락 보완
- **원인**: 수동 버튼 전환 과정에서 레이턴시 응답 제어용 AbortController 로직이 누락되어 연타 시 조언 오염 우려 발생.
- **해결**: `abortControllerRef`를 수동 핸들러 내에 선언하고 요청 시마다 취소 파이프라인을 이식해 최신 결과 보장.
- **상세**: [TROUBLESHOOTING.md #12](../TROUBLESHOOTING.md#12-수동-api-호출-버튼-전환에-따른-비동기-중복-요청race-condition-누락-보완)

### 13. 로컬 폴백(Fallback) 조언의 공수 상황 분기 정합성 결여
- **원인**: 백엔드 오류 시 폴백 엔진이 기준 구단의 공수 역할과 상관없이 무조건 투수 수비 조언만 제공함.
- **해결**: 이닝 진행에 따른 `myTeam` 공격/수비 역할을 판별하여 공격 시 타격 팁, 수비 시 피칭 팁으로 로컬 폴백 분기 구축.
- **상세**: [TROUBLESHOOTING.md #13](../TROUBLESHOOTING.md#13-로컬-폴백fallback-조언의-공수-상황-분기-정합성-결여)
